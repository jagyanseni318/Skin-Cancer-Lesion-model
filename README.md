# Code for "Explanation Reliability Beyond Diagnostic Accuracy in Dermoscopic Skin-Lesion Classification"

## Repository structure

```
requirements.txt          exact package versions used to produce the reported results
data/                      empty; see data/README.md for where to place HAM10000 and PAD-UFES-20
model/
  common.py                 shared config: paths, class definitions, model architecture,
                             loss, dataset split (lesion-level, seed 42), data loaders
  prep_cache.py              preprocesses HAM10000 (DullRazor hair removal, resize,
                             ImageNet normalisation) and caches images + masks as .npy
  prep_pad.py                same preprocessing for PAD-UFES-20 (with the >1024px
                             downscale-before-hair-removal step, documented in the paper)
  ita.py                     Individual Typology Angle (skin-tone proxy) for all
                             10,015 HAM10000 images, two definitions (v1, v2)
  train.py                   trains DenseNet121 for one seed (60-epoch one-cycle
                             schedule); run once per seed (42-46) and once more with
                             --epochs 100 --tag _ep100 for the convergence sensitivity check
  eval_seed.py                per-seed evaluation: temperature scaling, test/PAD-UFES-20
                             logits, Grad-CAM++, LSAS + null/ceiling baselines, permutation
                             test, deletion/insertion faithfulness, MC-dropout stability
  sts_fix.py                  recomputes the MC-dropout stability columns for an
                             already-evaluated seed (see "Known issues" below)
  domain_gap.py               domain-classifier AUROC, Frechet distance, image
                             statistics and the patient-level adaptation ladder for
                             the HAM10000 -> PAD-UFES-20 comparison
  analysis_cls.py             aggregates classification/calibration/convergence
                             results across all seeds -> model/out/results/
  analysis_xai.py             lesion-size geometric audit, faithfulness, stability,
                             skin-tone-proxy and correct-vs-misclassified analyses,
                             for every seed -> model/out/results/xai_all_seeds.json
  analysis_pad.py             stepwise decomposition of the PAD-UFES-20 performance
                             drop (population / label-space / prevalence / residual)
  make_figures.py             all 10 manuscript figures from model/out/results/
  ms_lib.py, ms_static.py,
  ms_results_cls.py,
  ms_results_xai.py,
  build_manuscript.py,
  build_audit.py              OPTIONAL: assemble the manuscript .docx/.md and the
                             results/integrity/submission audit directly from
                             model/out/results/, so every number in the text is
                             traceable to a specific line of code. Not required to
                             reproduce any numerical result; only needed to
                             regenerate the manuscript document itself.
  out/results/                the actual JSON/CSV outputs of the analysis scripts
                             above, as used to write the submitted manuscript
                             (included so tables/figures can be inspected or the
                             manuscript regenerated without rerunning training)
```

`model/out/` also normally contains `models/` (trained weights, ~350 MB),
per-seed `seed42/ … seed46/` folders (saliency maps, logits, per-image CSVs,
~100 MB each) and `figures/`, and `model/cache/` contains the preprocessed
image arrays (~2.6 GB). These are regenerated by running the pipeline below
and are not included here due to size; `out/results/` (the small, final
numerical outputs) is included.

## Reproducing the results

Run from inside `model/`, with `data/` populated as described in
`data/README.md`:

```bash
pip install -r ../requirements.txt

python prep_cache.py                     # HAM10000 image/mask cache
python prep_pad.py                       # PAD-UFES-20 image cache
python ita.py                            # skin-tone proxy for all HAM10000 images

for seed in 42 43 44 45 46; do
    python train.py --seed $seed --epochs 60 --workers 4
    python eval_seed.py --seed $seed
    python sts_fix.py $seed              # corrects MC-dropout stability (see below)
done
python train.py --seed 42 --epochs 100 --workers 4 --tag _ep100   # convergence check
python eval_seed.py --seed 42 --tag _ep100 --skip_faith

python domain_gap.py 42 43 44 45 46

python analysis_cls.py
python analysis_xai.py
python analysis_pad.py
python make_figures.py
```

`train.py` requires a CUDA GPU (mixed precision); the full 5-seed pipeline was
run on a single NVIDIA RTX 4050 Laptop GPU (6 GB) and took approximately 1
hour per seed for training and 15-20 minutes per seed for evaluation.

## Random seeds and reproducibility

- The train/validation/test split is lesion-level and uses a fixed split seed
  (42), identical across all five model seeds (`common.py:SPLIT_SEED`).
- Model seeds 42-46 (`common.py:SEEDS`) control head initialisation, the
  weighted sampler, augmentation, dropout, and the random baselines used in
  the explainability analyses (cross-image shuffle, toroidal shift, random
  patch order). They do not affect the data split.
- Explanation-analysis and faithfulness random number generators are seeded
  per model seed (`1000 + seed`, `2000 + seed`, `500 + seed` in `eval_seed.py`
  / `analysis_xai.py`) so that null baselines are themselves reproducible.

## Known issue fixed during the study (documented for transparency)

An earlier version of `eval_seed.py` constructed the MC-dropout stability
evaluator using `pytorch_grad_cam.GradCAMPlusPlus`, whose constructor calls
`model.eval()` internally; because this ran *after* dropout layers had been
set to `.train()`, all 15 stochastic passes were numerically identical and
stability was trivially 1.0 for every image. `eval_seed.py` in this
repository has the fix (dropout is re-enabled after the `GradCAMPlusPlus`
object is constructed); `sts_fix.py` is provided to recompute stability for a
seed that was evaluated before the fix, without repeating classification,
Grad-CAM++, LSAS or faithfulness computation for that seed.

## Data availability

HAM10000: https://doi.org/10.7910/DVN/DBW86T
PAD-UFES-20: https://doi.org/10.17632/zr7vgbcyr2.1

Both are public, de-identified datasets; no new patient data were collected.
